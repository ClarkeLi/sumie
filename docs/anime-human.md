# `anime_human` 风格：像人一样画

`--style anime_human` 在 `anime_study` 的感知层（Anime2Sketch 线稿、anime-seg 主体、调色板、`pacing.py` 截止时间）之上，重新做了「怎么画」：先线稿、后用油漆桶上色，每笔有压感粗细，节奏、停顿、笔顺像真人。它与 `anime_study` 并存。有压感用游戏自己的压感代码，没有压感也能画。

> 这是让画面和过程像手绘，不是用来伪装身份或绕过检测。公开房间请遵守根目录 README 的 Fair play。

## 1. 压感：游戏里到底能看到什么

读 `LinePressure.cs`、`ConfigureSize.cs`、`SmoothedValue.cs`：

- 打开「Stiftdruckerkennung」后，画的时候线宽实时跟着压力变，**只在本机可见**；
- 一笔画完，同步给所有人的 `LineInformation` **只有一个 `BrushSize`**；
- `BrushSize` = `Lerp(2, 35, 压力)` 取整，再经 `SmoothedValue(10).SmoothValue(5)`：10 帧环形缓冲，取第 5 新到第 9 新的 5 个读数的平均，抬笔前最后 4 帧不计；
- 压力 ≤ 0.05 的帧被当作「没按下」，不记点。

所以真人手绘板玩家的笔迹是：笔与笔之间粗细不同，一笔之内一致。`motor.py` 按这个行为模拟：每笔 `game_brush_size()`（游戏平滑的逐行移植）；压力读数按**游戏的帧率**（`--game-fps`，默认 240；`tools/probe_pen.py` 会测出来）一帧一帧取，因为它决定「第 5–9 新的帧」是抬笔前多久；压力始终保持在 0.062 以上直到抬笔，否则起笔和收笔会被游戏截掉，线接不上。

## 2. 两种画法，自动选择

`--pen auto`（默认）：游戏里压感打开且插件支持虚拟手绘板时用 `native`，否则 `direct`。

- `direct`：每笔画完后一次发给游戏，`size` 为模型算出的压感粗细。不需要压感，不需要虚拟笔。
- `native`：插件创建虚拟 `Pen` 设备，把每笔按 `[t_ms, x, y, 压力]` 逐帧回放，走游戏**自己的**输入路径，线真的一帧一帧长出来，`LinePressure` 自己算 `BrushSize`，自己简化点、同步、记录撤销。

`native` 的注意事项：回放期间不要动鼠标（`Pointer.current` 会变回鼠标，压力读数归零，这笔提前结束）；游戏在后台时，插件在这一笔内临时设 `backgroundBehavior=IgnoreFocus` 并打开 `runInBackground`，结束后恢复；连续 3 笔游戏都没接受就自动退回 `direct`。端点见 `api-reference.md`（`GET /api/v1/pen`、`POST /api/v1/stroke/pen`），`python tools/probe_pen.py` 先探测。

## 3. 画的顺序（v2）

画什么由 `anime_study.build_study` 决定（线稿、色块多边形、阴影），`anime_human.py` 只决定「像人一样怎么画」：

1. **线稿**：按部位聚类（上到下），长轮廓在前、短细节在后；笔画两端多出几格，像人收笔时越过交点；横线习惯左→右，竖线习惯上→下；
2. **Flatting（平涂）**：对每个色块，只在还没有线的地方沿多边形描边（描边用**该色块自己的颜色**，两头多出几格接在邻居的线上），再倒桶。桶先在离线模型里试倒：漏了就在逃逸路径最窄处补一笔短线；仍漏就整圈描边；色块被线条切成几块就每块倒一次；很小或很细的色块不倒桶，用一笔「点画」。线稿画在同一层，所以大多数色块的边已经被线稿封住，只需补缺的边；
3. **笔刷块、阴影**：粗笔、高压；
4. **细节线稿最后画**。

时间预算（针对 120 秒左右的短局调过）：线稿是骨架，占整局约 38 %——其中三分之二先画（轮廓和结构），三分之一留给颜色之后的内部细节（眼睛、衣褶、发丝）；平涂到 88 % 减去这份细节预留为止；之后若还有时间，继续平涂剩下的色块，而不是拉长停顿。描边和补口的线用**色块颜色的深色版本**（×0.62）画，而不是和色块同色：它们是看得见的线稿，让画面有骨架。平涂按「最便宜的先试」：先看现有的线能不能已经封住色块（直接倒桶），再试一两笔短线补口，最后才描边。完成度比细节重要：短局里线稿更少、颜色更多，保证画面在结束时是完整的。`--skill` 控制整体速度（默认 2.0，观众看到的是「很快的一笔接一笔」）。

### 笔压的两个细节

- 画面里「刚落笔」时游戏会晚一两帧才开始记线，起点会被削掉 1–4 格。所以每笔先在起点按住 70 ms 再移动；
- 每一帧压力都必须 > 0.05，否则游戏会把一笔拆成两笔。最细的线因此是 3（压力 0.052）。每笔的目标粗细来自 `anime_study` 的线宽，压力曲线再用游戏自己的平滑逻辑反推，使游戏存下的 `BrushSize` 命中目标。

## 3b. 回合时间：按整局规划，按剩余时间画

「自动读回合」时（不指定 `--time`）：

- **规划按这局的最长时间**（计时器的 `peak` = max(总时长, 已过 + 剩余)）：180 秒的局，哪怕开始画时只剩 120 秒，规划仍是 180 秒的那一幅；时间更长只会更多，不会少；规划内容的预算是 `peak − 30 s`；
- **执行必须在「当前剩余 − 30 秒」内画完**（短局最多留 40 %）。计时器每 6 秒重读一次，截止时间只会提前；
- **速度动态调整**：执行器每一笔前根据「剩余时间 ÷ 后面所有笔的自然时长」算出压缩比，同一幅画画得更快。压缩的是笔画时长和停顿；原生笔会把每笔的采样时间一起按比例压缩（落笔后的 70 ms 停顿保留）；压缩比最低 0.3（约快 3 倍）。仍然不够时，从计划末尾（最不重要的细节线稿）开始少画几笔。

例：180 秒规划的 290 个操作，只给 90 秒（截止 79 秒），实际 79 秒内画完 277 个，全部走原生笔，无一失败，倒桶无漏色。

指定 `--time N` 时保持旧行为（规划和预算都按 N，保留约 12 %）。

## 4. 节奏：来自真人涂鸦的统计

`tools/calibrate_motor.py` 读 Google Quick, Draw! 原始数据（带逐点时间戳的真人涂鸦，约 8.5 万笔），拟合单笔时长–长度幂律、笔间停顿、钟形速度剖面、曲率–速度幂律。结果提交在 `client/calibration/quickdraw_motor.json`，原始数据不入库。数据不含压力，压力曲线用手写和数位板研究中常见的「上升–平台–衰减」形态建模。

## 5. 漏色预测：离线桶模型

`client/bucket.py` 移植游戏的填充规则：0.02 世界单位的栅格，线按线宽 × 0.2 的半宽作墙，圆点不挡。执行时插件的 `/api/v1/fill` 返回 `regions[].area`，实际面积超过预测 1.8 倍就 `undo`，再用游戏里**真实的**线重新找口、补一笔、重倒（游戏会简化记录的点，偶尔出现模型没见过的口）。

## 7. 参数

| 参数 | 说明 |
|---|---|
| `--style anime_human` | 启用 |
| `--pen auto\|direct\|native` | 见第 2 节 |
| `--pressure 1.0` | 压力倍数；大于 1 线更粗 |
| `--skill 2.3` | 大于 1 画得更快更流畅 |
| `--game-fps 240` | 游戏帧率，决定压感窗口 |
| `--colour auto\|brush\|bucket` | 画笔分层涂色或油漆桶，见 7b |
| `--borders on\|off` | 画笔涂色之后，是否在线稿没有的地方给每个色块勾一圈深色边界线；`off` 时色块之间不勾线，只留最初的线稿。油漆桶需要封闭边界，不受影响 |
| `--virtual-layers 9` | 离线规划（`--dry-run`）时假定的层数 |
| `--time` / `--pace instant` | 与其他风格相同 |

Studio 里选「Anime Human」；`/api/v1/pen`、`tools/probe_pen.py` 用来检查虚拟笔。

## 7b. 虚拟图层与画笔涂色（`--colour brush`）

**为什么**：油漆桶要求区域被同一图层的线完全围住，漏一个口就整片冲出去，补口线（深色边）又让画面不干净。真人用的是图层：线稿一层，颜色在下面一层，随便涂，盖不住线。

**图层**：游戏只有三个排序层，不能新增，但每条线同步 `Layer` 和 `SortingOrder`，接收方按这两个值摆放。插件把 `SortingOrder` 切成区间，`(真实图层, 区间)` 就是一个虚拟图层，默认 3×3=9 层，别的玩家也看得到（细节见 `docs/api-reference.md` 的 `GET /api/v1/layers`）。`client/layers.py` 把角色映射到层号（9 层时）：

| 层 | 角色 | 内容 |
|---|---|---|
| 0 | `sketch` | （预留）|
| 1 | `flat` | 大色块 |
| 2 | `flat_top` | 小于总面积 2% 的色块 |
| 3 | `shade` | 阴影笔触 |
| 4 | `light` | 颜色点缀笔触 |
| 6 | `ink` | 线稿、补边 |
| 7 | `top` | （预留，线稿之上）|

少于 9 层时角色共用层（5 层是最低要求）；少于 5 层或插件没有 `/api/v1/layers`（旧插件、游戏没重启）自动回到油漆桶。`--colour auto`（默认）= 能用就用画笔。

**怎么涂**（`client/brush_fill.py`，在比桶模型细一倍的栅格上，笔号 s 就是 s 像素宽，和 `simulate` 用同一个笔迹形状）：
1. 色块 = 多边形去掉线稿覆盖的部分。允许的范围 = 色块 ∪（线稿 ∪ 之后才画的色块）在 18 格内的部分：笔可以压在线上、压在之后会盖掉它的色块上，但不会涂到白纸上，也不会盖住已经画完的色块。
2. 厚的地方（35 号笔装得下且有余量）：先沿边缘走一圈，再沿长轴来回扫（锯齿连成长笔）。
3. 剩下的细长部分（发丝、边缘）：取中轴线，在分叉处把走向相近的段接起来，每条用刚好够宽的笔（35/22/12/6/3）画一笔。
4. 每笔至少要新增覆盖面积的 4%，否则丢掉；覆盖目标 93%（小色块 85%），最外圈 1 格不要求（在线稿下面）。
5. 同色的色块连着画（尊重「后画的在上」的先后关系），少换色。第一轮每块都先有颜色，第二轮再收边（收边只在色块自己范围内，免得盖住邻居）。
6. 然后：没有线的色块边缘补一圈深色细边（在 `ink` 层），阴影和点缀笔触裁到「整支笔都落在色块里」的部分，最后是细节线稿。

实测（计划模拟，LPIPS 越低越好，其中 sanae 是一张绿发角色图）：

| 图 | 120 s 桶 → 画笔 | 180 s 桶 → 画笔 |
|---|---|---|
| marisa | 0.488 → 0.467 | 0.437 → 0.437 |
| in1 | 0.424 → 0.396 | 0.394 → 0.380 |
| in2 | 0.273 → 0.247 | 0.226 → 0.212 |
| sanae | 0.109 → 0.105 | 0.142 → 0.109 |

覆盖率（`tools/study_metrics.py`）也都更高（sanae 0.69 → 0.98）。画笔涂色的笔画多一倍左右，每笔都要一次请求，所以更依赖节奏压缩；120 s 局靠 `HUMAN_SPEED_FLOOR` 压到 0.3 倍。

**检查**：`python tools/probe_layers.py`（需要重启游戏装上新插件）：相邻虚拟层两两交叉，先画高层再画低层，从截图量交叉处，直接笔画和虚拟笔各一遍，输出 `LAYERS OK`。房间里别的玩家和相册是否一致，需要另一台电脑确认。

## 9. 被画框切掉的图：边缘要自然

原图里被画框切掉的人物（半身像、截断的腿/手/头发）如果照抄，会在切口处留下一条笔直的边，一眼就能看出是照着图片画的。`client/frame_cut.py`（`--soften-frame auto|on|off`，`anime_human` 默认开，`anime_study` 默认关）：

1. 检测每条图片边上人物与边相接的区段；
2. 用一条向人物内部弓起、带慢波和微颤的不规则曲线替换直边，把人物蒙版裁到这条曲线上（弓起 5 % 的人物大小）；
3. 靠近曲线的线稿在随机位置收笔，一部分变成越来越短、越来越淡的「消失线」；
4. 沿新边缘不画墨线，也不画深色边：色块在一堵「看不见的、起伏的墙」前结束（墙用色块本身的颜色）。

`python tools/frame_check.py 原图 plan.json` 数值检查：沿每条被切的边，绘画停在同一个像素位置的比例（flat）。照抄是 0.76–1.0，现在是 0.2–0.35；> 0.4 退出码为 1。代价：因为裁掉了约 5–8 % 的人物，与原图的 LPIPS 会稍差（约 0.005–0.03），这是有意的。

## 9b. 计划和实际画出来为什么不一样（以及怎么量）

`python tools/compare_actual.py plan.json 游戏截图.png --save-dir 目录`（截图用 `GET /api/v1/screenshot?path=…`）：用线条的包围盒把模拟结果和游戏截图对齐，输出：镂空（计划里有、游戏里没有的颜料占比）、多余、线条墨量比、线宽。用它查出三件事：

1. **预览画得比实际粗、笔画两头是圆的。** 游戏的线宽正好是 `size / 100` 世界单位（实测 size 3→3.2 px … 26→28 px，画布 108 px/世界单位），线头是平的、折角是圆的；旧的 `simulate()` 用整数粗细并加了圆头。现在 `simulate()` 按游戏的方式画（3 倍超采样、平头、圆折角），预览与实际：镂空 0.0 %、墨量比 0.95、线宽 5.7 vs 5.5 px。
2. **有的倒桶几乎没倒出东西。** 一次把脸部（预期 0.0095）只倒出 0.0001：点击点离墙只有 1.4 格，游戏把点击落到自己的网格里，落在了墙另一侧的「口袋」中。三处对策：种子改取**真实格子里最深的点**（不是色块多边形的中心），并保存 2 个备用点（`Op.alt`）；执行时比预期小于 35 % 的倒桶先撤销，再依次点备用点，实在不行就撤销、不留碎点；模型里的墙按游戏的方式先做 0.01 世界单位的简化。
3. **边与填充之间的白色细缝。** 游戏填充多边形与模型格子几乎一致（差 0.4–2 %），细缝来自细线；区域边界/补口笔画默认 4 号（`HAND_BORDER_SIZE`），缝隙与镂空明显减少。

另外 Studio 过去把笔固定为 `direct`、速度固定为 1.0，与命令行默认（`auto`、2.3）不一致；现在 Studio 不再指定，使用渲染器默认值。

## 10. 踩过的坑：新填充会被下一笔改色

游戏在每次填充后让这块填充保持「可选中」状态（填充工具的悬停预览：下一次落笔会用当前颜色给它重新上色）。游戏平时在你切换到别的工具时统一关闭它；桥接从不切换工具，于是**下一笔或下一次换色之后，所有填充都变成最后用的那个颜色**（`/api/v1/lines` 里能看到）。两处对策：插件在每次 `RealFill` 之后调用 `LineFillable.SetLineSelectActive(false)`（和 `ActivateTool` 的做法一致，需要重启游戏生效）；执行器在每次倒桶后调用 `tool("Brush")`（无需重启，也像人「倒完桶回到画笔」）。`python tools/probe_fill_colors.py` 检查前一项。

## 11. 已知限制

- 调色是按封闭区域的中值，柔和的渐变会成平色，阴影靠圈出的暗部补一点；
- 极细的补口线（压力接近 0.05 的下限）在游戏里不易看见，但会挡住油漆桶；
- 同步效果最好在私人房间用另一台电脑确认。
